## 4. Test di regressione: metodo usato dallo sviluppatore (solo lettura)

Non ho rimesso il codice vecchio (vietato dal task). Ho verificato **per lettura** che il test è
discriminante:

- il test monta la `PreventiviScreen` vera dentro un `GoRouter` minimo con due rotte sentinella:
  `/preventivi/nuovo` → `Text('EDITOR NUOVO')` e `/preventivi/:id` → `Text('EDITOR <id>')`;
- il servizio dati è un finto (`_ServizioPreventiviFinto`) che restituisce due preventivi `p1` e `p2`
  (via `spServiceProvider.overrideWith`), quindi nessun accesso a Firebase;
- il test tocca la card `ValueKey('preventivo-p2')` e asserisce `find.text('EDITOR p2')` **e**
  `find.text('EDITOR NUOVO')` = `findsNothing` (`test/preventivi_screen_test.dart:330-334`).

Con la vecchia `_apriPreventivo(Preventivo _) { context.go('/preventivi/nuovo'); }` il clic porta alla rotta
`/preventivi/nuovo`, quindi comparirebbe `EDITOR NUOVO` e l'asserzione `EDITOR p2` fallirebbe: il test
copre esattamente il difetto. Il secondo test (id vuoto) copre il ramo di sicurezza aggiunto dalla
correzione (`if (id.isEmpty) return;`).
